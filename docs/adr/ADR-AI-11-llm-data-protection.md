# ADR-AI-11: LLM에 보내는 데이터를 어떻게 보호할 것인가

> 상태: 제안 · 오너: 김연재 · 작성: 2026-11-01. 확정 전까지 승인된 결정이 아니다.

## Context

- 결정할 질문: 코드와 증거의 비밀 값, 입력에 숨은 지시를 LLM 호출 전후에 어떻게 처리할 것인가?
- 현재 문제와 배경: 입력에 키나 내부 자산 정보가 섞일 수 있다. Notion OPTION C도 LLM 호출 전 마스킹을 요구한다.
- 범위: LLM으로 나가는 데이터와 프롬프트 경계를 다룬다.

## Decision Drivers

1. 비밀 값이 외부 LLM과 응답으로 나가지 않는다.
2. 패치와 설명에 필요한 맥락은 남긴다.
3. 입력 글을 명령으로 해석하지 않는다.

## Considered Options

### Option A: 패턴 마스킹과 비신뢰 경계 (현재 구현)

- 설명: 호출 전 `redact`로 코드와 근거 값을 가리고, 응답 설명도 다시 가린다. 입력을 `<untrusted_data>`로 감싼다. 패치에 비밀 값이 있으면 거절한다. 시크릿 인벤토리는 값이 아닌 이름만 받는다.
- 장점: 구현이 작고 외부 도구 없이 동작한다. 코드 맥락이 남아 패치가 가능하다.
- 단점 및 위험: 패턴에 없는 비밀 값은 지나간다. 마스킹되지 않은 코드 자체는 외부 LLM으로 나간다. 비신뢰 경계는 지시문을 완전히 막지 못하므로 ADR-AI-04와 함께 동작한다.

### Option B: 전용 비밀 탐지기 추가

- 설명: gitleaks 등으로 호출 전에 한 번 더 검사한다.
- 장점: 탐지 범위가 넓어진다.
- 단점 및 위험: 의존성과 실행 시간이 늘어난다. 오탐이 코드를 가려 패치를 망칠 수 있다.

### Option C: 코드는 보내지 않고 SARIF만 전송

- 설명: 스캐너 결과와 짧은 설명만 보낸다.
- 장점: 외부로 나가는 정보가 크게 준다.
- 단점 및 위험: 오탐 분류와 패치를 할 수 없어 AI 수정 시나리오가 빠진다.

### Option D: 로컬 LLM

- 설명: 코드가 외부로 나가지 않게 내부 모델을 쓴다.
- 장점: 데이터 위치 설명이 가장 강하다.
- 단점 및 위험: GPU 운영과 품질 재검증이 필요하다. 시연 일정 대비 위험이 크다.

## Decision

- 선택: Option A
- 결정 이유: 시연 범위에서 필요한 맥락을 유지하면서 대표 비밀 값 유출을 줄인다. 데모 앱에 실제 고객 코드를 쓰지 않는다는 전제에서 충분하다.
- 감수한 트레이드오프: 소스 코드 자체가 외부 LLM으로 전달된다. 패턴 기반이라 누락이 있을 수 있다.
- 결정자: 미정 / 결정일: 미정
- 다시 볼 조건: 실제 사내 코드를 넣는 시나리오나 데이터 주권을 시연 항목으로 잡으면 Option B, D를 다시 본다.

## Follow-up

- 코드가 외부 LLM으로 나간다는 점을 발표 질문에 대비해 정리한다.
- 데모 앱 설정 형식으로 마스킹 테스트를 추가한다.
