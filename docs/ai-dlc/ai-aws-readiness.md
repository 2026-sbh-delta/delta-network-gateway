# 사용자 진단 AWS 릴리스와 기능 준비 상태

2026-11-06 사용자 요청: 사용자 AWS에 먼저 올려 확인하고, AWS→GCP/온프레미스·로그 근거·판단 데이터·처리 불가 입력의 실제 범위를 확인한다.

## 승인 범위와 설계

기존 사용자 진단 EC2 `10.90.10.90`의 delta-ai를 최신 검증된 시험본 API/규칙/문서로 갱신한다. 현재 팀 오케스트레이터 `10.90.10.75`의 그래프/실행 기록은 보존하고 호출자에서 새 API를 검증한다. 사용자 실행 요청을 기존 기능의 릴리스/검증 승인으로 적용한다. 팀의 진행 중인 Terraform/운영 배포 풀체인은 수정하지 않는다.

정본 main 기반의 독립 worktree에 recovery-local의 AI 소스/시험/문서를 고정했다. 런타임 파일/비밀값은 복사하지 않는다. 진단과 복구 제안 API만 기존 private HTTPS/토큰 경계로 노출한다. 기존 CA/토큰/환경/볼륨/로그 설정을 보존하며 이전 컨테이너를 복구 가능하게 유지한다. IAM/SG/DNS·고객 앱/DB는 변경하지 않는다.

## 작업과 성공 기준

1. 기존 서버 소스/상태/설정 조회, 최신 AI 전체 회귀 실행.
2. 커밋된 소스의 ARM64 digest 생성, state 없는 후보 컨테이너에서 인증/스키마 검증.
3. 기존 진단 컨테이너만 교체하고 사설 NGINX에 인증된 recovery-proposals 경로 추가. 실패 시 기존 컨테이너/NGINX 복구.
4. 실제 오케스트레이터 출발 TLS/인증/실제 Claude 진단·복구 제안 확인. 잘못된 입력/빈 근거/없는 인용/모델 실패/미지원 데이터의 경계를 검증한다.
5. 중앙 로그 도착과 자동 근거 수집을 구분한다. AWS/GCP/온프레미스별 실제 검증과 남은 연결을 보고한다.

## 초기 확인

- 기존 진단 host: delta-ai healthy, private NGINX는 diagnoses만 노출한다. 이미지0f419e3.
- 현재 오케스트레이터: 이전 실제 화면 검증 이미지e2ba16d8 유지, 미완료 실행0/기록28개. 진단 필수1, 차분/온프레미스 고급 복구 연결 없음.
- AI 전체 회귀317개 통과(1.86초). 네트워크/실제 모델이 아닌 로컬 회귀다.
- 중앙 CloudWatch AWS/GCP 그룹 모두 storedBytes>0. 도착 자체는 자동 진단 입력 활용의 증거가 아니다.

## 1차 실제 AWS 릴리스

AI 소스6f65166의 ARM64 digest177de19d를 기존 사용자 호스트에 실제 배포했다. 기존 CA/토큰/환경/로그/볼륨을 보존하고 이전 컨테이너를 stopped로 유지했다. NGINX는 사설 diagnoses와 recovery-proposals만 노출한다. 실제 오케스트레이터 출발로 TLS/인증·실제 Claude 진단2건/복구 제안2건을 확인했다. 잘못된 필드/빈·중복 근거422, 과대 본문413, 익명401. AWS 중앙 로그의 GuardDuty1건은 sample=true, GCP12건은 ALLOWED라는 제한을 실제 모델이 구분했다. 미지원 자원/로그 권한 부족/비신뢰 승인 지시는 사람 확인/운영자 대기로 남았다. 이는 자동 수집이 아니라 수동 제한 조회를 입력한 검증이다.

실제 배포된 AI 라이브러리에 합성 입력으로6방향 매핑을 실행했다. AWS↔GCP 기본 사양 대응은 pass, 온프레미스 포함 방향은 선언/실측 부족 또는 미지원 kind 때문에 needs_human. 실제 고객 앱/DB/DNS 이전 성공을 뜻하지 않는다.

## 후속 개선 승인과 설계 — 로컬 ADR 제안(팀 번호 미할당)

사용자 추가 지시 `개선할 작업 진행`에 따라 중앙 로그 자동 수집과 처리 불가 정보 표시부터 개선한다. 팀의 진행 중인 운영 배포/Terraform 풀체인은 수정하지 않는다.

- 그래프가 예외 분석 직전에 고정3개 CloudWatch 그룹을 조회한다. 자기 run_id 로그는 직접 연결하고 중앙 AWS/GCP는 환경 참고로만 표시한다. 최근 최대10분/실행 시작 이후, 그룹당최대40건·2페이지·짧은 네트워크 timeout, 원문/주소/비밀값 없이 상태·분류·샘플·미해석 건수만 전달한다.
- 조회 불가/빈 결과/미해석/잘림·환경과 실행의 연관성 미확인·시험 이벤트를 명시한다. AI가 이를 누락하거나 실패해도 서버가 제한 문구를 보고서에 보존한다. 새로운 판정/자동 승인을 만들지 않는다.
- case별 원본 요청 해시에 묶은0600 요약 캐시를 원자 저장한다. 재시작은 같은 근거를 사용하고 변조/충돌/크기 실패는 명시적 공백으로 남긴다. 스캐너 근거를 잘라 환경 로그로 대체하지 않는다.
- 기존 역할에는 로그 쓰기만 있으므로 별도 `terraform/orchestrator-evidence-aws` root에서 `logs:FilterLogEvents`를 세 그룹에만 허용하는 정책1건을 추가한다. 기존 역할/기본 정책/IAM 배포 권한/SG/DNS/Secret 경로는 변경하지 않는다.
- 최신 전체 회귀: AI319개1.79초, pipeline/orchestrator144개14.61초 통과. Terraform mock1개(역할·Action·3그룹assertion) 통과. 실제 Plan 생성1/변경삭제0 확인. 아직 후속 Apply/이미지/자동 수집 실측 완료로 기록하지 않는다.

최종 배포·자동 수집 검증은 후속 기록에 기입한다. 근거는 루트 notes/ai-aws-readiness-20261106이다.
