# 프로젝트 삭제

## 요청·승인과 범위

2026-11-05 사용자가 프로젝트 삭제 버튼을 요청했다. 기존 API에 삭제 기능이 없음을 설명하고,
앞선 프론트엔드 전용 범위의 예외로 이번 기능에 한해 **최소 백엔드 변경 포함**을 명시적으로 승인받았다.
목록에서 프로젝트로 지칭한 항목은 기존 `Service` 등록이다. 팀 공통 `projects` 작업 공간은 삭제하지 않는다.

## 설계·구현 계획

- 목록 각 행에 독립된 삭제 버튼을 둔다. 등록 정보·검사 이력이 영구 삭제됨을 설명하고 정확한 이름을 입력받는다.
- native dialog에서 취소/Escape와 포커스 복귀를 지원한다. 요청 중에는 중복 제출과 닫기를 막는다.
- 기존 인증·Origin·CSRF 보호가 적용되는 `POST /api/v1/services/{id}/delete`를 사용한다. 본문은 `confirmation_name`만 허용한다.
- 등록 행 잠금을 새 작업 접수와 공유한다. queued/running 작업(취소·정리 대기 포함), 연결된 환경, 이전·배포 계획이 있으면 409로 차단한다.
- 삭제 가능한 경우 한 트랜잭션에서 해당 서비스의 run event → run → service만 삭제한다. 다른 서비스와 공통 작업 공간을 유지한다.
- 같은 ID의 재요청은 204로 처리한다. 사라진 행의 요청은 새로 등록한 같은 이름의 다른 ID에 영향을 주지 않는다.
- 성공 후 목록·서랍·환경 선택 저장소를 갱신한다. 오래된 목록 응답으로 삭제된 항목이 되살아나지 않도록 기존 load generation을 무효화한다.
- GitHub 저장소·실제 클라우드 자원·이미지·Jenkins 기록 삭제, 실행 중인 작업의 자동 중단, 환경/계획 강제 정리는 범위 밖이다.

## 운영·복구

삭제는 플랫폼 기록의 영구 삭제다. 사용자 확인창에서도 복구 불가를 알린다.
삭제된 실제 기록의 복구는 운영 DB 백업 복구 절차가 필요하며 웹 복구 버튼은 제공하지 않는다.
코드에 문제가 있으면 이전 플랫폼 버전으로 롤백한다. 롤백 자체가 삭제된 기록을 되살리지는 않는다.
