도메인과 로그인 상태를 유지합니다

프론트엔드, 백엔드, PostgreSQL이 함께 움직이는 서비스를 기준으로 합니다. 아래 로컬 시연 결과는 클라우드 이전이 끝났다는 뜻이 아닙니다.

로컬 전체 흐름에서 확인한 내용

별도 Docker PostgreSQL 17 원본·대상과 같은 고정 Docker 앱 이미지를 사용해 실제 Playwright 브라우저로 확인했습니다.

로그인과 주소로그인 1회 · 서비스 URL 유지 · 세션 쿠키 유지
데이터와 앱복사 전·CDC 중 기록 확인 · 대상 DB에 새 기록 저장 · 앱 이미지 ID 동일
전환 중단 시간통제된 쓰기 중지 4.332초 · 상태 확인에서 의도적으로 측정한 HTTP 503 17회, HTTP 200 12회
접속 경로로컬 Nginx는 루프백 데모 진입점만 담당합니다. 운영용 추가 로드 밸런서나 HAProxy 복귀를 제안하지 않습니다.

가용성 표현: 실제로 일시적인 503이 관찰됐으므로 무중단 이전으로 표현하지 않습니다.

클라우드 이전은 별도 검증이 필요합니다

  • AWS에서 GCP로 VM·VPN·PostgreSQL을 옮기는 실제 이전은 아직 실행하지 않았습니다.
  • GCP 프로젝트 GCPterm2-delta에는 10.30.1.0/24 서브넷이 있지만, 현재 VM 0대·VPN 0개입니다.
  • 플랫폼 웹의 계획 승인은 계획에 대한 승인 기록만 남깁니다. 데이터 복사나 전환을 시작하지 않으며, 현재 실제 이전 실행은 운영자 CLI로 진행합니다.
  • 이 로컬 증거는 원격 CI의 이전 검증 결과나 클라우드 적용 결과가 아닙니다.

의도한 이전 절차

1 · 초기 복사PostgreSQL 기준 데이터를 대상으로 복사
2 · CDC 동기화복사 중 발생한 변경을 따라잡기
3 · 대상 검증격리된 DB에서 앱·데이터·세션 확인
4 · 승인과 전환쓰기 잠금, 최종 동기화, 단일 작성자 전환

기존 도메인과 로그인 세션을 유지하고, 전환 전에는 구·신 앱이 같은 쓰기 DB를 사용합니다. GCP와 온프레미스는 각각 연결·앱·DB를 따로 검증하며 한 공유 데이터 계층의 쓰기 주체는 하나로 둡니다.

복구 경계: 대상 DB 쓰기가 시작된 뒤에는 DNS만 원복해도 안전한 롤백이 되지 않습니다. 사전 계획한 역방향 동기화나 별도 복구 절차 없이 이전 DB로 되돌리지 않습니다.

검증 범위는 로컬 브라우저와 두 PostgreSQL 데이터베이스입니다. 실제 클라우드 복제·전환과 원격 CI 검증은 별도 작업으로 남아 있습니다.
