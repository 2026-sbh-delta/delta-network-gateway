# 플랫폼 발표 화면 구현

기준: 2026-11-05. 사용자 제공 `PLATFORM_FRONTEND_PLAN.md`와 후속 지시인
“플랫폼 프론트엔드만 변경”을 구현 범위와 승인 근거로 삼았다.
변경 범위는 `platform/web`이며 백엔드·다른 서비스·인프라는 변경하지 않는다.

## 설계와 구현

- 기존 AppShell의 왼쪽 서랍과 서비스별 경로를 유지한다.
- 개요는 버전 준비 요약, 단계 이동, 구성 요소, AWS/GCP/온프레미스의 실제 관측 순으로 정리한다.
- 빌드 화면은 구성 요소와 대상별 검사 요약을 먼저 보여주고 기존 실행·취소·재시도 화면을 보존한다.
- 계획 화면은 새 계획 작성, 최근 계획 선택, 대상별 환경 차이, AI 설명·diff, 승인 범위, 실행 기록을 제공한다.
- 이미지는 빌드 ID로, 환경은 환경 ID로 연결한다. 최신 실패·취소 기록에 연결 정보가 없으면 이전 성공을 대신 표시하지 않는다.
- SAST 발견 0건, DAST 미실행, 검사 실패·완료를 구분한다. SAST 성공을 운영 배포 승인으로 표시하지 않는다.
- 대시보드는 기존 실제 지표·로그·trace 조회와 기본 15분/최대 2시간/30초 갱신을 유지한다. 환경 선택은 서비스별 세션 저장소에 보존한다.
- 긴 digest와 계획 해시, diff는 상세로 접는다. 상태는 글자와 색상으로 표시하고 390px에서는 카드를 한 열로 배치한다.

## 기존 API로 연결된 범위

서비스, 빌드, SAST/DAST/실행 검사, 환경 목록·관측, workflow·execution 목록·계획 승인을 기존 경로 그대로 사용한다.
운영 화면에 fixture나 임의의 성공 결과를 주입하지 않는다. API 오류는 오류·재조회로 표시한다.
출발/대상의 지역·등록 버전 비교는 기능 동등성 검사 결과가 아니다.

## 아직 서버에서 제공하지 않는 선택적 조회 정보

프론트엔드의 아래 타입은 향후 공개 조회 응답을 위한 **제안 계약**이다.
현재 백엔드가 제공한다고 가정하거나 새 API를 호출하지 않는다. 이 계약의 실제 저장·검증·배포 연동은 이번 작업에 포함하지 않는다.

| 기존 응답의 선택적 필드 | 프론트엔드 사용 | 필드가 없을 때 |
| --- | --- | --- |
| `Service.application_bundle` | 버전, DB 구성, FE·BE 서비스/빌드 ID를 명시적으로 연결 | 단일 서비스 기록·묶음 미연결 |
| `Execution.assessment` | workflow·환경·plan hash·assessment ID가 일치하는 공개 차이/제안/diff | 실제 환경 분석 결과 미연결 |
| `Observability.application` | 묶음 버전·구성 요소 서비스/빌드 ID에 맞는 readiness·실제 커밋/digest | 구성 요소 관측 미연결 |

타입은 `application-model.ts`, `EnvironmentComparison.tsx`, `observability-api.ts`에 있다.
서비스 이름이나 저장소 이름으로 FE·BE를 추정하지 않는다. 다른 프로젝트/서비스의 빌드는 제외한다.
묶음 정보가 `memory` 또는 `none`인 경우 DB 미구성으로 표시하며 메모리 데이터의 보존을 주장하지 않는다.
제안 계약의 예시는 `tests/release.spec.ts`의 브라우저 HTTP fixture에서만 사용한다.
AI의 raw tool payload·비밀값을 공개 응답으로 보내서는 안 된다. 프론트엔드는 승인된 공개 projection만 받도록 타입을 제한한다.

실제 승인 API는 단일 이미지와 대상 환경의 계획 승인이다. FE·BE 묶음 승인, AI 코드 변경 승인,
운영 배포 실행, 서비스 주소의 실제 환경·버전 검증은 서버 연동 전까지 완료로 표시하지 않는다.
검증된 운영 주소 계약이 없으므로 임의의 서비스 열기 링크를 만들지 않는다.
기존 로그인·CSRF·서버 승인 경계는 유지한다.
