## 왜 위험한가
VLAN 과 방화벽으로 나뉜 환경에서는 뚫린 노드가 번질 범위가 좁다. 카페나 공유기 같은 개방망은 같은 망의 기기와 게이트웨이에 그대로 닿고, 호스트 방화벽까지 없으면 SSH 와 API 서버가 함께 노출된다.
설정을 신고받는 것만으로는 구분할 수 없어서 실제 연결 시험으로 판단한다.

## 판정 기준
막혀야 할 경로가 열렸거나 노드에 공인 IP 가 있으면 네트워크 계층은 열림이다. 양성 대조가 실패하면 닫힘 결과를 믿지 않고 확인 불가로 둔다.
호스트 방화벽이 기본 허용이어도 관리 가능한 상위 방화벽이 격리를 실측으로 보장하면 통과한다. 상위 방화벽을 관리할 수 없으면 호스트 방화벽이 기본 거부여야 한다. 어느 경우든 바깥 지점에서 노드로 건 연결 시험이 있어야 격리로 인정한다.

## 고치는 법
상위 방화벽을 관리할 수 있으면 VLAN 으로 나누고 내부 대역과 관리 포트 경로를 막는다.
관리할 수 없으면 공유 장비 변경을 권하지 않는다. 호스트 방화벽을 기본 거부로 켜고 관리 포트는 WireGuard 나 Tailscale 터널에서만 연다.
k3s 에서 ufw 를 켜면 파드와 서비스 대역(기본 10.42.0.0/16, 10.43.0.0/16)을 허용해야 한다. NodePort 는 INPUT 룰로 막히지 않으므로 쓰지 않으면 닫고 외부에서 다시 시험한다.
