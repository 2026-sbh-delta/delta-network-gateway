# ADR-AI-32: 온프레미스 시험 환경을 어디에 어떻게 둘 것인가

> 상태: 제안 · 오너: 김연재 · 작성: 2026-11-02. 시험 환경은 이미 만들었지만, 본선 범위에 넣을지는 팀 합의 전이다.

## Context

- 결정할 질문: 온프레미스 시연과 시험에 쓸 환경을 어디에 두고, 실제 운영 중인 홈 네트워크를 어떻게 보호할 것인가?
- 현재 문제와 배경: 11/01 회의에서 온프레미스는 후순위로 두고, 가능 여부는 김연재가 조사하기로 했다. 쓸 수 있는 장비는 개인 홈 서버뿐이고, 같은 네트워크에 운영 서비스가 돌고 있다.
- 범위: 장비와 네트워크 위치, 원복 방법, 팀 망 연결 경로를 다룬다. 격리 판정은 [ADR-AI-33](ADR-AI-33-network-posture.md)에서 다룬다.

## Decision Drivers

1. 시험 공격과 이전 실패가 운영 서비스에 닿지 않아야 한다.
2. 본선 후 원래 상태로 되돌릴 수 있어야 한다.
3. 팀 중앙 망(TGW·ANF)을 지나는 구조와 맞아야 한다.

## Considered Options

### Option A: 가상화 호스트에 전용 VM을 만들고 빈 VLAN에 격리

- 설명: 쓰지 않던 IoT VLAN에 k3s 단일 노드 VM을 올린다.
- 장점: VM을 지우면 흔적이 대부분 사라지고, 다른 내부 대역은 방화벽으로 막힌다.
- 단점 및 위험: 라우터 VM과 같은 thin pool을 써서 pool이 가득 차면 집 라우터도 멈춘다. 집 전원과 회선이 끊기면 시연도 멈춘다.

### Option B: 운영 k3s 노드를 그대로 사용

- 설명: 이미 돌고 있는 클러스터에 배포한다.
- 장점: 구축이 필요 없다.
- 단점 및 위험: 공개 서비스와 VPN 라우터가 같은 노드에 있어 시연 실패가 운영 장애가 된다. 메모리 여유도 적다. 물리 서버라 스냅샷으로 되돌릴 수 없다.

### Option C: 다른 개인 장비 사용

- 설명: GPU 노드나 보조 PC에 올린다.
- 장점: 운영 노드와 분리된다.
- 단점 및 위험: 보조 PC는 접속되지 않았다. GPU 노드는 WSL 구조에 재부팅마다 콘솔 로그인이 필요하다.

## Decision

- 권고: Option A. 크기는 4코어, RAM 5GB, 디스크 20GB로 했다.

세부 결정은 다음과 같다.

| 결정 | 선택 | 이유 |
|---|---|---|
| 원복 방법 | VM 생성 전에 라우터 VM 스냅샷과 설정 기준본을 호스트와 NAS에 보관한다. 원복은 설정 복원을 기본으로 한다 | 전체 롤백은 집 네트워크가 끊겨 리허설하지 못했다 |
| 게이트웨이 룰 | 전 포트 허용을 DNS·NTP만 허용으로 좁히고, 방화벽 자신으로 가는 트래픽을 막는다 | 룰 설명과 달리 VM에서 라우터 관리 포트에 닿을 수 있었다 |
| VLAN 대역 | `10.10.40.0/24` 를 `10.40.0.0/24` 로 바꾼다 | 팀 Client VPC `10.10.0.0/16` 과 겹쳐 VPN 경로를 만들 수 없다 |
| 팀 망 연결 | Cloudflare Tunnel 대신 VPN 지점으로 붙인다 | Tunnel은 트래픽이 ANF를 거치지 않아 중앙 검사 구조와 맞지 않는다 |
| 샘플 앱 | podinfo와 PostgreSQL을 쓴다 | 고객 앱이 정해지기 전에 웹, DB, 재시작을 시험하기 위해서다 |

보류한 것: 시연 안정성(행사장 경로, 예비 환경)은 사용자가 뒤로 미뤘고, VPN 요청은 사용자가 시점을 정해 직접 보낸다. 대회 규칙은 사용자가 문제없다고 확인했다.

## Consequences

- 긍정: Mac에서 건 k6 부하 시험 400 rps에서 실패 0건, p95 4.35ms, 노드 CPU 4%였다. 100 rps 중 rolling restart도 실패 0건이었다. VM 강제 종료 뒤 웹은 약 27초, DB는 28초에 돌아왔고 데이터도 유지됐다. 수치는 집 안 경로 기준이다.
- 부정: AWS 쪽 VPN이 없어 클라우드와 잇는 이전 시연은 아직 할 수 없다. 집 회선 경유 성능과 외부망 접속도 시험하지 못했다. 공인 IP가 DHCP라 본선 전날 다시 확인해야 한다.
- 원복 시 주의: 기준본을 복원하면 게이트웨이 전 포트 허용 룰도 함께 돌아온다.
- 후속 작업: 팀의 범위 결정, VPN 적용과 터널 구성, 시연 안정성 대책, 본선 후 원복.

## Security & Compliance

- 공인 IP, 호스트 주소, 라우터 설정 원본은 저장소에 넣지 않는다. 라우터 `config.xml` 에는 비밀값이 있다.
- 다른 내부 대역은 BGP로 광고하지 않고 `10.40.0.0/24` 만 내보낸다.
