# ADR-AI-40: 전체 흐름을 무엇이 구동할 것인가

> 상태: 제안 · 오너: 김연재 · 작성: 2026-11-02. 1단계(로컬 이식)만 구현했고 팀 확정 전이다. 확정되면 ADR-AI-27 의 "Jenkins 구동"을 대체하고, ADR-AI-06 의 Option B 와 ADR-AI-24 의 Option B 를 판단 서비스 밖에 한해 다시 본 결과가 된다.

## Context

- 결정할 질문: 온프레미스 증거·SAST·DAST·판단·배포를 잇는 흐름을 Jenkins 가 구동할 것인가, 에이전트가 Jenkins 를 도구로 호출할 것인가?
- 배경: 11/02 준우 님이 Jenkins 빌드·배포를 도구로 두고 에이전트가 호출하는 구조와 LangGraph 를 제안했다. SAST·스테이징 설계도 상위 에이전트 호출을 전제한다. 김연재가 그래프 상태·게이트 구조를 맡겠다고 답했다.
- 배경: 시연 콘솔의 `flow.py` 가 이미 같은 일을 직접 짠 코드로 하고 있었다. 수정 반복과 경로 분기는 Jenkinsfile 에 넣으면 코드와 진행 화면이 지저분해진다.
- 범위: 흐름 구동만 다룬다. 판정 규칙은 그대로이고 판단 서비스 내부에는 LangGraph 를 넣지 않는다.

## Decision Drivers

1. 실행 주체가 자기 실행을 판정하지 않는다(ADR-AI-04·05).
2. 데모에서 같은 순서로 재현된다. 입력 글이 전이를 바꾸지 못한다.
3. 배포 권한은 Jenkins 에 남고, 구동자가 죽어도 롤백은 돈다.
4. 본선(11/07)까지 끝낼 수 있고, 안 되면 돌아갈 곳이 있다.

## Considered Options

### Option A: Jenkins 구동

- 장점: 추가 구현이 가장 적다. 구동과 권한이 한곳에 있다.
- 단점: 수정 반복·진행 그래프를 Jenkinsfile 과 별도 이벤트로 만들어야 한다. DAST 가 루프백 전용이라 지금도 시연은 콘솔이 구동한다.

### Option B: 고정 전이 그래프가 구동, Jenkins 는 도구

- 설명: 전이를 코드로 고정한 LangGraph 그래프가 서비스를 호출한다. LLM 은 delta-ai·DAST 안에서만 쓴다.
- 장점: 재개, 사람 승인, 그래프 시각화를 직접 짜지 않는다. 미리 돌려 승인 앞에 세워 두면 ADR-AI-31 의 시연 방식과도 맞는다.
- 단점: `langchain-core`·`langsmith` 가 함께 설치된다. 멱등과 대상별 잠금은 직접 구현해야 한다. 담당의 일이 늘어난다.

### Option C: LLM 이 도구를 골라 진행

- 장점: "에이전트" 설명이 가장 강하다.
- 단점: 순서가 입력과 모델에 달려 재현과 게이트 보장이 어렵다.

## Decision

- 선택: Option B 권고, Option C 기각. 사용자 승인으로 1단계만 구현했다.
- 안전 조건: `durability="sync"`, 배포 직전 게이트 재확인, Jenkins 빌드 `RUN_ID` 멱등, 롤백은 Jenkins 유지.
- 철회 기준: 11/03 오전까지 1단계가 끝나지 않으면 `flow.py` 로 돌아간다. 재개와 그래프 기반 시각화만 포기한다.
- 감수한 트레이드오프: 1단계는 기능이 늘지 않는 이식이다. 이득은 재개와 이후 단계의 자리뿐이고 시연 흐름은 같다.
- 결정자: 미정 / 결정일: 미정
- 다시 볼 조건: AWS·GCP 배포 경로가 Jenkins 안에서 더 단순하게 끝나거나, 그래프 운영 위치를 정하지 못할 때.

## Consequences

- 흐름 코드가 `deploy/demo-console` 에서 `services/delta-pipeline` 으로 옮겨졌고, 콘솔은 화면과 입구만 맡는다.
- Jenkins 작업에 `RUN_ID` 파라미터가 늘었다.
- SAST·스테이징 설계의 "상위 관리 에이전트"를 이 그래프로 읽을 수 있다. 다만 LLM 이 도구를 고르지 않는다는 점은 준우 님과 맞춰야 한다.

## 아직 정하지 않은 것

- **이전 경로(최우선):** 그래프의 순서와 도구 계약(`delta_pipeline/migration.py`)만 있고 구현은 대역이다. 실제 프로비저닝·배포·전환·복제를 누가 어떻게 구현하는지 정해야 한다.
- **실행 위치(제안):** Jenkins 와 그래프는 플랫폼 VPC `10.80.0.0/16` 사설 서브넷의 x86 EC2 한 대(`t3.medium`부터)에서 돌리고, 콘솔은 SSM 포트 포워딩으로 연다. 테스트하지 않았고 Terraform 도 없다.
- **트래픽 전환(제안):** ALB 가중치와 IP 대상 그룹. 서울 리전에 IP 대상 그룹이 있는 것만 확인했고 GCP 주소로 시험하지 않았다. 사설망(VPN)이 있어야 한다.
- **쓰기 위치(제안):** 쓰기 전환 전까지 쓰기는 출발지 DB 한 곳으로 간다. 복제 방식과 함께 동규 님 확인이 필요하다.
- **Jenkins 분리:** 스테이징과 DAST 대상 등록이 생기기 전에는 얻는 것이 없어 미뤘다.
- **수정 반복:** `fix_review` 판정은 구현했지만(ADR-AI-28) 그래프에 잇지 않았다. 패치 빌드를 스테이징에 올리고 DAST 대상으로 등록하는 경로가 먼저 필요하다.
- **HTTP API·취소·대상별 잠금:** 콘솔 밖에서 호출할 때 만든다.
- **게이트 대조 범위:** 패치 뒤에는 커밋이 바뀌므로 이전 판단은 환경 스냅샷, SAST·DAST 는 이미지에 묶어야 한다.
