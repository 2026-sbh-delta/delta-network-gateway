# ADR-AI-08: 어떤 LLM 모델을 쓸 것인가

> 상태: 제안 · 오너: 김연재 · 작성: 2026-11-01. 확정 전까지 승인된 결정이 아니다.

## Context

- 결정할 질문: 설명, 오탐 분류, 패치 제안에 어떤 모델을 쓸 것인가?
- 현재 문제와 배경: 기본값은 `claude-sonnet-5-5`다. 이 모델로 실제 평가 13건을 통과했다. 다른 모델과는 아직 비교하지 않았다.
- 범위: 모델 선택만 다룬다. 호출 경로는 ADR-AI-09에서 다룬다. 가격은 입력/출력 100만 토큰당 Anthropic API 정가이며 2026-10-06 기준 목록이다.

## Decision Drivers

1. 코드 패치가 실제로 적용되고 취약점을 고친다.
2. 호출당 비용과 지연이 시연과 반복 평가에 맞다.
3. 모델을 바꿔도 코드 변경이 작다.

## Considered Options

### Option A: Claude Sonnet 5.5, $2/$10 (현재 구현)

- 설명: 모든 판단에 한 모델을 쓴다.
- 장점: 평가를 통과한 유일한 조합이다.
- 단점 및 위험: 함수 호출을 따라가야 하는 어려운 코드에서 Opus보다 약할 수 있으나 측정하지 않았다.

### Option B: Claude Opus 5.5, $4/$20

- 설명: 품질을 우선한다.
- 장점: 복잡한 코드 판단과 패치 품질이 더 좋을 것으로 기대한다.
- 단점 및 위험: 토큰 단가가 Sonnet의 2배이고 응답이 더 오래 걸릴 수 있다. 시연 입력이 작으면 차이가 안 보일 수 있다.

### Option C: Claude Haiku 5.5, $0.10/$0.50

- 설명: 비용을 우선한다.
- 장점: 반복 평가 비용이 크게 줄어든다.
- 단점 및 위험: 패치 품질과 인용 준수가 떨어지면 `needs_human`이 늘 수 있다. 측정하지 않았다.

### Option D: `kind`별 모델 분리

- 설명: 환경 차이 설명은 Haiku, 코드 보안은 Sonnet 이상으로 나눈다.
- 장점: 필요한 곳에만 비용을 쓴다.
- 단점 및 위험: 평가와 프롬프트 조정 대상이 늘어난다.

### Option E: 다른 제공사 모델·로컬 모델

- 설명: 다른 상용 모델이나 Ollama 등을 쓴다.
- 장점: 제공사 종속이 줄고, 로컬은 코드가 밖으로 나가지 않는다.
- 단점 및 위험: 구조화 출력과 품질을 다시 검증해야 한다. 이번 기간에는 평가하지 않았다.

## Decision

- 선택: Option A 유지
- 결정 이유: 지금 검증된 조합이 이것뿐이고 예선에서도 같은 판단을 했다. 모델 이름은 환경 변수로 바꿀 수 있다.
- 감수한 트레이드오프: 더 싸거나 더 좋은 모델이 있을 수 있는데 비교 없이 고른 상태다.
- 결정자: 미정 / 결정일: 미정
- 다시 볼 조건: 데모 앱 코드로 평가했을 때 패치 실패가 나오면 Option B를 비교한다.

## Follow-up

- 데모 앱이 정해지면 평가셋으로 Sonnet, Opus, Haiku를 비교한다. 실제 호출 비용이 든다.
- **위험:** Sonnet 5.5는 thinking 설정을 생략하면 adaptive thinking으로 돌고 안전 분류기가 `cyber` 범주를 거절할 수 있다. 현재 `MAX_TOKENS`는 8000이어서 긴 입력에서 출력이 잘릴 수 있다. 잘리면 `LLM_OUTPUT_INVALID`, 거절되면 코드 보안에서 `LLM_UNAVAILABLE`로 사람에게 넘어간다. 실제 공격 보고서로 시험한다.
- 환경 변수 이름 `REVIEW_LLM_MODEL`은 예선 이름이므로 `DELTA_LLM_MODEL`로 바꾼다.
