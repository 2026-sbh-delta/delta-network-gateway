# ADR-AI-26: 온프레미스 실측 증거를 어떻게 판단에 넣을 것인가

> 상태: 제안 · 오너: 김연재 · 작성: 2026-11-02. 확정 전까지 승인된 결정이 아니다. 코드는 브랜치 `feat/onprem-integration` 에 있다.

## Context

- 결정할 질문: 온프레미스에 배포한 뒤의 시나리오, 취약점, 로그, 방화벽 상태를 판단 서비스에 어떤 형태로 넣을 것인가?
- 현재 문제와 배경: 온프레미스 VM에서 연동을 시험했더니 `identity: none` 이 항상 unknown 이었고, kube-bench를 SARIF로 넣으면 k3s 오탐이 실패로 남았으며, 방화벽과 실제 도달성은 입력이 없었다. 차단된 공격은 finding이 없어 근거가 남지 않았다.
- 범위: 판단 서비스 계약과 규칙, 읽기 전용 수집기를 다룬다. 온프레미스 배포 자체와 VPN은 다루지 않는다.

## Decision Drivers

1. LLM이 아니라 코드가 판정하고, 수집 실패를 통과로 읽지 않는다.
2. 원본 로그와 CVE 목록을 그대로 보내지 않아 LLM 입력을 작게 유지한다.
3. 방화벽 변경처럼 영향이 큰 조치는 자동으로 적용하지 않는다.

## Considered Options

### Option A: 새 `runtime_security` kind와 전용 입력

- 설명: 패키지별로 묶은 취약점, 오탐 표시한 점검, 집계한 로그 신호를 받는다. 도달성과 방화벽은 기존 `migration_parity` 에 선택 입력으로 넣는다.
- 장점: 입력이 작고 규칙이 코드로 판정한다. 측정한 오탐 근거가 결과에 남는다.
- 단점 및 위험: 계약이 커지고 호출자나 수집기가 변환을 맡는다.

### Option B: 전부 SARIF로 변환해 `code_security` 로 보냄

- 설명: 추가 계약 없이 기존 호출을 쓴다.
- 장점: 구현이 거의 없다.
- 단점 및 위험: 실측으로 통과한 사실과 오탐 근거를 담지 못한다. 시험에서 이미지 스캔 결과가 항목 수백 개로 늘었다.

### Option C: 원본 로그와 스캔 결과를 LLM에 맡김

- 설명: 원본을 그대로 보내고 LLM이 요약하고 판단한다.
- 장점: 수집기가 단순하다.
- 단점 및 위험: 비용이 크고, 공격자가 쓴 로그 문자열이 프롬프트에 그대로 들어간다. LLM이 판정하지 않는다는 원칙과 충돌한다.

## Decision

- 권고: Option A. `verified_controls` 를 결과에 추가해 막혔다고 실측된 통제를 남긴다.
- 이유: 판정은 코드에 두면서 시연에서 "무엇이 막혔는지"까지 근거로 보여 줄 수 있다.

격리 수준이 다른 환경은 `network_posture` 로 구분한다.

- 판정: 네트워크, 노드, 클러스터 계층을 실측해 `isolated`, `partial`, `open`, `unknown` 으로 코드가 정한다. 양성 대조가 실패하거나 게이트웨이만 시험했으면 격리로 인정하지 않는다.
- 제안: 코드가 `upstream_firewall` 에 따라 조치를 고른다. 개방망에는 호스트 방화벽과 터널을, 관리 가능한 환경에는 VLAN 과 방화벽 룰을 제안한다.
- 노드: 호스트 방화벽이 기본 거부여도 NodePort 는 INPUT 룰로 막히지 않으므로, 바깥 지점의 연결 시험이 있어야 격리로 인정한다.
- 경계: 설정한 대상과 기본 게이트웨이만 시험한다. 남의 네트워크에서 주변 기기를 스캔하지 않는다.

## Consequences

- 긍정: 실제 VM에서 수정 전 방화벽 룰은 `PAR-NET-003` 실패, 현재 룰은 통과로 갈렸다. kube-bench FAIL 8건 중 7건이 근거와 함께 오탐으로 정리됐다. NetworkPolicy 적용 전후로 태세가 `partial` 에서 `isolated` 로 바뀌었다.
- 부정: 로그의 공격 판별은 시연용 문자열 패턴이라 정상 요청을 잘못 잡거나 공격을 놓칠 수 있다. 방화벽 파서는 pf(OPNsense)만 지원한다. 호스트 방화벽은 iptables 기본 정책만 읽어 nftables 전용 룰은 허용으로 보인다. 바깥 지점 시험은 호출자가 고른 한 지점의 결과라 다른 경로의 노출까지 보장하지 않는다.
- 후속 작업: 팀 결정, 호출 주기와 호출 주체 결정, `deployment_gate` 작업과 계약 병합.

## Affected Components

- `delta_ai/contract.py`, `parity.py`, `runtime.py`, `adapters.py`, `service.py`, `scripts/collect_onprem.py`, `knowledge/rules/`

## Security & Compliance

- 수집기는 설정을 바꾸지 않는다. 다만 시험 공격 요청을 보내고 스캔용 파드를 잠시 만든다. 환경 변수는 이름만 보내고, 로그 표본은 마스킹하며, 목적지 주소를 표본에서 뺀다.
