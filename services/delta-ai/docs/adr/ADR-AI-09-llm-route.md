# ADR-AI-09: LLM을 어떤 경로로 호출할 것인가

> 상태: 제안 · 오너: 김연재 · 작성: 2026-11-01. 확정 전까지 승인된 결정이 아니다.

## Context

- 결정할 질문: Anthropic API를 직접 부를 것인가, 클라우드 제공 경로를 쓸 것인가?
- 현재 문제와 배경: 지금은 API 키로 직접 호출한다. 시연은 AWS에서 GCP로 옮기는 내용이고 주제는 Beyond Lock-In이다.
- 범위: 호출 경로만 다룬다.

## Decision Drivers

1. 앱이 어느 클라우드로 옮겨 가도 AI 판단이 그대로 돈다.
2. 키와 권한 관리가 안전하다.
3. 비용을 어느 계정으로 처리할 수 있는지 명확하다.

## Considered Options

### Option A: Anthropic API 직접 호출 (현재 구현)

- 설명: `ANTHROPIC_API_KEY`로 호출한다.
- 장점: 특정 클라우드에 묶이지 않는다. 지금 동작하고 새 기능을 바로 쓸 수 있다.
- 단점 및 위험: 장기 키를 직접 보관한다. 코드와 설명이 Anthropic으로 나간다.

### Option B: Amazon Bedrock

- 설명: IAM 권한으로 Bedrock의 Claude를 호출한다.
- 장점: 장기 키가 없고 팀 AWS 계정 비용으로 처리할 수 있다.
- 단점 및 위험: AWS에 묶인다. 가격이 별도이고 모델 사용 권한 확인이 필요하다.

### Option C: Google Vertex AI

- 설명: GCP 권한으로 호출한다.
- 장점: 이전 대상 환경과 맞출 수 있다.
- 단점 및 위험: GCP에 묶인다. 시연 전 환경 구성이 추가된다.

### Option D: 사내 LLM 게이트웨이

- 설명: LiteLLM 같은 프록시를 앞에 둔다.
- 장점: 제공자 전환과 비용 집계를 한곳에서 한다.
- 단점 및 위험: 해커톤 범위에서 운영할 구성요소가 하나 늘어난다.

## Decision

- 선택: Option A 유지. 팀이 AWS 비용 처리를 요구하면 Option B로 바꾼다.
- 결정 이유: AI 서비스가 이전 대상 클라우드에 묶이지 않아야 이전 전후 판단이 같다. 판단 코드는 `LlmClient` 프로토콜만 알아 경로 교체 범위가 어댑터로 제한된다.
- 감수한 트레이드오프: 키를 직접 관리한다. 클라우드 자격 기반 호출보다 보안 설명이 약하다.
- 결정자: 미정 / 결정일: 미정
- 다시 볼 조건: 주최 측 크레딧이 특정 클라우드에만 있거나 코드 외부 전송에 제한이 있으면 다시 본다.

## Follow-up

- 팀 AWS 계정에서 Bedrock Claude 사용이 가능한지와 비용 처리를 확인한다.
- Bedrock으로 바꾸면 구조화 출력은 제공되지만, 어댑터를 실제로 평가셋에 돌려 확인한다. 아직 시험하지 않았다.
