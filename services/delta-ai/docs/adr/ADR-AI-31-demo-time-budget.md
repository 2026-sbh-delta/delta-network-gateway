# ADR-AI-31: 5분 발표에서 파이프라인을 어떻게 보여 줄 것인가

> 상태: 제안 · 오너: 김연재 · 작성: 2026-11-02. 팀 결정이 필요하다. 전체 소요 시간은 아직 측정하지 않았다.

## Context

- 결정할 질문: 발표 5분(통역 제외) 안에 배포 파이프라인 중 무엇을 라이브로 보여 줄 것인가?
- 현재 문제와 배경:
  - 측정값은 로컬·가짜 LLM 기준 파이프라인 전체 약 11~15초(빌드 #53~57), 사전 확인 중단 7초(#63)이다.
  - 부분 실측은 `/fix` 26초, Claude 패치 13.1초, 실패 분석 4~5초다. 판단 호출 제한은 최대 약 2분(60초×2회)이다. SAST 빠른 모드 목표 60초는 설계값이다. DAST 1회와 실제 클라우드 빌드·배포, 전체 흐름은 측정하지 않았다.
  - 이 ADR 은 5분 기준인데 스테이징 설계 문서는 시연 시간을 7분으로 적었다. 확인이 필요하다.
  - 11/02 회의에서 시간이 모자라면 목 데이터를 쓰고 CSP 를 병렬로 보여 주는 안이 나왔다. 준우 님 설계는 환경을 미리 띄우고 이미지만 바꾼다.
  - 호원 님은 Jenkins 화면까지는 안 보여 줘도 될 것 같다며 논의를 제안했다.
- 범위: 파이프라인 시연 구간만 다룬다. 발표 전체 구성은 다루지 않는다.

## Decision Drivers

1. 정해진 시간을 넘기지 않는다.
2. 핵심 장면이 외부 장애로 끊기지 않는다.
3. 실제로 동작한 결과만 보여 준다.

## Considered Options

### Option A: 사전 실행 + 핵심 장면만 라이브

- 설명: 빌드·점검·정상 배포 결과는 미리 돌려 보여 주고, 카나리 10% 에서 자동 롤백되는 장면만 라이브로 실행한다.
- 장점: 2분 정도에 맞출 수 있고 판단과 롤백을 보여 준다.
- 단점 및 위험: 전 과정이 라이브는 아니다. 사전 실행임을 밝혀야 한다.

### Option B: 전 과정 라이브

- 설명: 코드 push 부터 100% 승격까지 발표 중에 실행한다.
- 장점: 가장 설득력 있다.
- 단점 및 위험: 판단 세 번이 제한값까지 걸리면 그것만 6분이다. 지연과 네트워크 장애에 그대로 노출된다.

### Option C: 녹화본만 사용

- 설명: 전체를 영상으로 보여 준다.
- 장점: 시간과 장애 위험이 없다.
- 단점 및 위험: 실제 동작을 증명하는 힘이 약하다.

## Decision

- 선택: Option A 권고, 녹화본은 대비책으로 준비한다.
- 화면: Jenkins 대신 단계와 판정을 보여 주는 진행 그래프를 우선 검토한다(ADR-AI-24). 임시 시연 콘솔에 단계 화면이 있지만 로컬 전용이다. 정식 담당과 구현 방식은 정해지지 않았다.
- 감수한 트레이드오프: 실제 LLM 응답이 느리면 미리 받은 응답을 보여 줄 수 있고, 이때는 그렇게 밝힌다.
- 결정자: 미정 / 결정일: 미정
- 다시 볼 조건: 실측 결과 전체가 2분 안에 안정적으로 끝나는 경우.

## Follow-up

- 실제 Claude·DAST·실제 환경을 포함한 전체 실행 시간을 측정한다.
- 라이브 시연 장면과 진행 그래프 담당을 팀에서 정한다.
- 발표 전 불량 릴리스 기록을 초기화하는 절차를 리허설에 넣는다.
